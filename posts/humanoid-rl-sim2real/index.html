人形机器人 RL：从 Isaac 训练到实机部署

仿真里能跑能跳的策略，到实机上秒躺，几乎全是 sim2real gap。这篇把人形 RL 从训练配置到上机调试的整条链路拆开，重点讲清楚域随机化该随机什么、观测里该放什么、以及实机侧必须做的几层保护。

人形机器人的 RL 运控这两年进展很快，但工程上的难点不在算法——PPO 就够用——而在仿真与实机之间的差距。仿真里 100% 成功率的策略，直接上机大概率撑不过 3 秒。

训练侧：观测与动作怎么定#

人形 20~30 自由度，全状态观测维度很高。我的经验是观测只给策略必要的量，多余的只会让 sim2real 更难。

text
观测 (obs):
  基座: 重力投影(3) + 角速度(3) + 线速度(3, 仿真特权)
  关节: 位置(23) + 速度(23)
  上一动作(23)
  相位时钟: sin/cos(2)              # 步态相位，比让策略自己学更稳
  指令: 线速度(2) + 偏航角速度(1) + 高度(1)

动作 (action):
  23 维关节目标位置增量，经 PD 转成力矩
线速度别用仿真特权

仿真里能直接拿到真实基座线速度，实机上只能靠状态估计（腿部运动学 + IMU 融合），误差不小。训练时必须给线速度加噪声，否则策略会过度依赖一个现实中拿不到的高精度量。我的做法是加高斯噪声 + 随机延迟。

域随机化：随机什么最有性价比#

域随机化不是"什么都随机"。按投入产出排序，我实际开的有：

随机项范围收益
质量 / 质心位置±15% / ±3cm高。负载与装配误差的主要来源
关节 PD 增益±25%高。不同批次电机差异很大
地面摩擦0.3 ~ 1.2高。瓷砖到橡胶垫
电机力矩延迟0 ~ 4 ms高。实机总线与驱动都有延迟
观测噪声按实测标定中高
地形（高度场）平滑噪声中
外部推力随机 50~150 N中
电机模型（力矩上限、齿隙）轻量随机中
电池电压±10%低但便宜
不要随机化"不可能发生"的东西

早期我给关节加了 ±60% 的 PD 增益随机，策略学得非常保守——因为它要照顾一个现实中根本不存在的极端机器人。结果是能走但走不快，也跳不起来。随机化范围的边界要用实测数据画，不是怕不够就放大。

实机侧：三层保护#

策略网络输出的是目标关节位置，直接下发电机很危险。实机上我加了三层：

cpp
// 第 1 层：动作限幅与变化率限制
target = clamp(target, joint_limits.lo, joint_limits.hi);
target = clamp(target, last_target - max_delta, last_target + max_delta);

// 第 2 层：状态合理性检查
if (!estimator.healthy() || base_pitch > 0.9 || base_roll > 0.9) {
    enter_damping_mode();   // 切阻尼，慢慢蹲下
    return;
}

// 第 3 层：硬件兜底（独立于上位机线程）
if (current > current_limit || temp > temp_limit) {
    hardware_estop();
}

第三层一定要在实时控制器里独立实现，不能依赖上位机——上位机崩了的时候，机器人还在通电。

状态估计：实机上最容易出问题的一环#

人形没有轮式编码器，基座速度只能估。我用的是：

  1. 腿部运动学（关节编码器 + 正运动学）算出支撑脚到基座的相对速度
  2. IMU 积分得到姿态与角速度
  3. 用卡尔曼滤波融合，输出基座线速度

接触判定错了，估计就会飞。 判定用足底力 + 关节力矩残差双重条件，比单看足底力可靠得多。

python
def contact_state(foot_force, joint_torque_residual, thresh_f=30.0, thresh_t=8.0):
    # 两个条件都满足才认为接触，避免误判导致速度估计跳变
    return (foot_force > thresh_f) and (abs(joint_torque_residual) < thresh_t)

课程学习：别一上来就要求走路#

人形比四足难，因为质心高、支撑面小。我的课程是：

  1. 站立：只要求保持高度与姿态，指令速度全 0
  2. 抗扰站立：加随机推力，要求不倒
  3. 原地踏步：引入相位时钟
  4. 低速行走：0.3 m/s 以内
  5. 速度跟踪：0.3 ~ 1.2 m/s，含转向
  6. 地形与扰动：斜坡、台阶、随机推力

每一阶段达到成功率阈值再进下一阶段。跳过站立直接学走路，策略会学到"摔倒前快速蹬腿"这种投机解。

实测结果#

23 自由度人形，Isaac Lab 训练，4096 并行环境，Orin NX 上部署（策略推理 0.6 ms）：

阶段仿真成功率实机成功率
站立抗扰（150N 侧推）99.8%96%
0.8 m/s 直线行走99.5%92%
含转向行走98.7%85%
12° 斜坡97.2%78%

实机成功率普遍比仿真低 10~20 个百分点，差距主要来自状态估计误差，不是动力学建模——这一点从"指令越复杂差距越大"能看出来。

提高实机成功率最有效的一件事

把状态估计的误差模型接进训练。具体做法：录制实机运行时的估计输出与真值（动捕或外部视觉），拟合出误差的统计特性，然后在仿真里把它作为观测噪声注入。这一步能吃掉一半以上的差距。
