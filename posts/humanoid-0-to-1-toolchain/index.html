小机器人导出URDF展示#

在机器人的结构设计完成后（通常在结构设计前还需要进行关节电机、传感器选型和硬件架构设计等），需要导出URDF（Universal Robot Description Format）是一种用于描述机器人模型（如连杆、关节、运动学参数、可视化模型等）的XML 文件格式。

https://wiki.ros.org/urdf

  • 在结构导出为URDF后，我们需要检查各个部分的质心、惯量、碰撞等属性，以确保该文件的准确性。

我们可以使用以下网站进行检查：https://viewer.robotsfan.com/

  • URDF 导出及检查详细请参考：

零件检查#

确保

  • 零件完整性检查：没有零件缺失、错位、错误的情况
  • 零件惯量检查：确保惯量的数值与实际一致
  • 零件质心检查：确保零件的质心正确

关节检查#

确保

  • 坐标轴一致：关节的坐标轴一致，均为右手坐标系
  • 旋转轴一致：关节旋转轴统一指向坐标轴正方向
  • 限位检查：保证限位符合实际要求（如：机械结构限位、电气软件限位等）

小机器人通讯SDK#

小机器人通讯中间件#

小机器人通讯sdk使用fastdds作为通讯中间件，IDL（Interface description language）作为统一的接口管理。

https://github.com/eProsima/Fast-DDS

在编写相关sdk时，需要先确定IDL的内容，如

bash
idl
├── BmsState.idl
├── ButtonEventType.idl
├── ImuState.idl
├── LowCmd.idl
├── LowState.idl
├── MotorCmd.idl
├── MotorState.idl
├── RpcReqMsg.idl
└── RpcRespMsg.idl

其中，BmsState为电池信息、ButtonEventType为遥控按钮信息、ImuState为IMU信息、MotorCmd为发送给关节电机的信息、MotorState为关节电机返回的信息、LowCmd整合了可以发送的底层信息、LowState整合了接收到的所有底层状态信息、RpcReqMsg和RpcRespMsg用于实现RPC的数据包装。

小机器人SDK封装#

通过fastddsgen，将idl生成为对应的C++代码。

https://github.com/eProsima/Fast-DDS-Gen

通过以上方式，再加上具体对fastdds的通讯实现，即可封装cpp相关的sdk代码。

为了方便使用，还需将其绑定到python实现。

使用pybind11作为python封装接口：

https://github.com/pybind/pybind11

通过自定义stg文件可以做到自动生成idl对应的pybind11封装：

以LRLowStateSubscriber为例：

cpp
// 具体实现
class __attribute__((visibility("hidden"))) LRLowStateSubscriber
    : public std::enable_shared_from_this<LRLowStateSubscriber> {
   public:
    explicit LRLowStateSubscriber(const py::function& py_handler) : py_handler_(py_handler) {}
    void InitChannel() {
      // ......
    }
    void CloseChannel() {
      // ......
    }
   private:
      // ......
};

// 绑定到python
py::class_<robot::little_robot::LRLowStateSubscriber, std::shared_ptr<robot::little_robot::LRLowStateSubscriber>>(
    m, "LRLowStateSubscriber")
    .def(py::init<const py::function&>(), py::arg("handler"), R"pbdoc(
            // ...注释
        )pbdoc")
    .def("InitChannel", &robot::little_robot::LRLowStateSubscriber::InitChannel, "Init low state subscription channel")
    .def("CloseChannel", &robot::little_robot::LRLowStateSubscriber::CloseChannel,
         "Close low state subscription channel");

将其安装到系统即可使用相关python sdk，这是小机器人封装sdk的方式，也可以直接通过python相关的dds通讯直接实现python sdk。

然后就可以通过sdk编写一些程序来进行可视化/调试。详细见1.6小节。

提前验证#

  1. 提前验证算法所需硬件频率及性能

实机通讯频率未知的情况下，可以通过提前通过设置硬件频率来验证算法所需硬件频率。

如imu设置为 50hz（左）与 45hz（右） 的情况

  1. 提前验证算法鲁棒性

通过部署代码（与真机代码类似）直接和mujoco进行通讯，通过完全异步的控制方案来验证算法。

此时应当检查电机参数是否合理，如仿真中关节力矩持续超过电机额定力矩，这会电机导致过热无法长时间运行。

  • 若存在电机完全无法满足要求的情况，需要进行重新硬件选型。
  • 若算法存在完全无法使用该结构设计的情况，需要重新进行结构设计或更换算法方案。

通用层common文件夹下的核心实现#

  1. ROBOTLOG日志系统

日志库通过spdlog库实现封装，能自动存储日志文件，并防止日志过多造成溢出，日志文件存储在"/var/log/robot/"路径下，核心代码如下：

cpp
void ensure_initialized() {
    if (!robot_logger) {
        if (LOG_ASYNC_MODE) {
            spdlog::init_thread_pool(LOG_Q_SIZE, LOG_THREAD_POOL_SIZE);
            auto console_sink = std::make_shared<spdlog::sinks::stdout_color_sink_mt>();
            robot_logger =
                std::make_shared<spdlog::async_logger>("robot-logger(async)", console_sink, spdlog::thread_pool(),
                                                       spdlog::async_overflow_policy::overrun_oldest);
        } else {
            robot_logger = spdlog::stdout_color_mt("robot-logger");
        }
        robot_logger->set_level(static_cast<spdlog::level::level_enum>(LOG_DEFAULT_LEVEL));
        robot_logger->set_pattern(LOG_PATTERN);
        robot_logger->enable_backtrace(LOG_BACKTRACE_SIZE);
        spdlog::flush_every(std::chrono::milliseconds(LOG_FLUSH_TIME));
        spdlog::set_default_logger(robot_logger);
        if (!LOG_CONSOLE_SHOW) {
            auto& sinks = robot_logger->sinks();
            sinks.erase(std::remove_if(sinks.begin(), sinks.end(),
                                       [](const spdlog::sink_ptr& sink) {
                                           return std::dynamic_pointer_cast<spdlog::sinks::stdout_color_sink_mt>(
                                                      sink) != nullptr;
                                       }),
                        sinks.end());
        } else {
            robot_logger->info(LOG_START);
        }
    }
}

  1. 物理层通讯库

该部分实现分两种情况：

  • 所使用的硬件模块，厂商已经提供Linux下的SDK（如USB2CAN模块），只需要引入相关实现即可。
  • 所使用的硬件模块需要底层通讯支持，如支持CAN通讯的电机，直接通过CAN线连接至主控PC，那则需要对CAN通讯进行封装以方便后续在HAL层实现对电机的控制。

小机器人所使用的硬件只需要实现USB串口通讯即可。

  1. HAL实现

根据硬件所使用的通讯协议实现对应的HAL接口，这样后续更换硬件只需要重新实现对应的HAL接口即可，无需在其他层进行大幅度修改。

注：可能存在不同硬件之间接口形式完全不同或不直接支持HAL接口功能的情况，如某些电机可能不支持PD控制，这种情况考虑更换硬件或通过硬件提供的功能来尝试实现接口功能。

  • 有限状态机的实现为：

通过定义下面的数据结构，并注册对应的Callback函数，可以得到右图的转换关系，切换状态后会回调注册的Callback函数，实现状态模式切换。

static const auto DAMPING_STATE =

    std::pair<int, std::string>(static_cast<int>(RobotMode::Prepare), RobotModeToString(RobotMode::Prepare));

    std::pair<int, std::string>(static_cast<int>(RobotMode::Walking), RobotModeToString(RobotMode::Walking));
static const auto CUSTOM_STATE =
    std::pair<int, std::string>(static_cast<int>(RobotMode::Custom), RobotModeToString(RobotMode::Custom));
static const ChangeStatePath DAMPING_PATH = {DAMPING_STATE, PREPARE_STATE, CUSTOM_STATE};
static const ChangeStatePath PREPARE_PATH = {DAMPING_STATE, PREPARE_STATE, WALKING_STATE};
static const ChangeStatePath WALKING_PATH = {DAMPING_STATE, PREPARE_STATE, WALKING_STATE};

  1. gRPC通讯

目前通过DDS实现RPC通讯，gRPC通讯实现可以实现网络穿透等功能，目前没有必须要使用gRPC通讯的内容，仅介绍基于DDS的RPC功能，它通过IDL定义响应和请求数据类型，包括请求头和数据体，类型均为string类型，可通过 json 格式发送请求/响应，服务端通过客户端发送数据头中的 UUID（通用唯一标识符）来实现响应匹配。目前 UUID 的生成方法为随机生成。

RPC通用错误码如下：

cpp
const int64_t RpcStatusCodeSuccess = 0;                  // success
const int64_t RpcStatusCodeTimeout = 100;                // request timeout
const int64_t RpcStatusCodeBadRequest = 400;             // bad request, usually when the request param is invalid
const int64_t RpcStatusCodeInternalServerError = 500;    // internal server error
const int64_t RpcStatusCodeServerRefused = 501;          // server refused the request
const int64_t RpcStatusCodeStateTransitionFailed = 502;  // robot state machine transition failed
const int64_t RpcStatusCodeInvalid = -1;  // default value, usually when the request has not been sent yet

RPC 客户端封装例子：

cpp
enum class LocoApiId {
    ChangeMode = 2000,
};
/**
 * @brief Change robot mode
 *
 * @param mode robot mode, options are: kDamping, kPrepare, kWalking
 *
 * @return 0 if success, otherwise return error code
 */
int32_t ChangeMode(robot::robot::common::RobotMode mode) {
    auto change_mode = ChangeModeParameter(mode);
    std::string param = change_mode.ToJson().dump();

  1. 机器人后台进程封装 daemon.hpp文件

该头文件的主要实现包括：

  • 包含CrashHandler函数用于在程序崩溃时候自动存储崩溃调用栈，并写入日志
  • Daemon类带有一个Watchdog和SocketServer，可以通过向本地的sock发送数据来进行简单的程序启动和停止控制，同时带有软看门狗防止后台程序因为异常抛出或错误码停止工作。
cpp
void CrashHandler(int sig) {
    // get proc name
    static char name_buf[PATH_MAX];
    static char* base_name_buf = nullptr;
    ssize_t len = readlink("/proc/self/exe", name_buf, sizeof(name_buf) - 1);
    if (len != -1) {
        name_buf[len] = '\0';
        base_name_buf = ::basename(name_buf);
    }

    // open crash file
    time_t t = time(nullptr);
    char filename[256];
    if (base_name_buf == nullptr) {
        snprintf(filename, sizeof(filename), "%s/crash_%ld_%d.log", robotlog::LOG_DIR, t, getpid());
    } else {
        snprintf(filename, sizeof(filename), "%s/%s_crash_%ld_%d.log", robotlog::LOG_DIR, base_name_buf, t, getpid());
    }
    auto crash_fd = open(filename, O_CREAT | O_WRONLY | O_APPEND, 0644);
    if (crash_fd < 0) {
        crash_fd = STDERR_FILENO;
    }

    // print call stack
    dprintf(crash_fd, "[Crash] Caught signal %d\n", sig);
    void* array[CRASH_STACK_SIZE];
    int size = backtrace(array, CRASH_STACK_SIZE);
    backtrace_symbols_fd(array, size, crash_fd);
    _Exit(1);
}

作为Daemon类的子线程之一，可以接受本地 socket 通讯，用于实现对任务的动态简单配置。客户端直接通过Linux下的命令发送字符串。

void SocketServer() {
        int server_fd = socket(AF_UNIX, SOCK_STREAM, 0);
        if (server_fd < 0) {
            perror("socket");
            return;
        }
        unlink(socket_path_.c_str());
        struct sockaddr_un addr;
        memset(&addr, 0, sizeof(addr));
        addr.sun_family = AF_UNIX;
        strncpy(addr.sun_path, socket_path_.c_str(), sizeof(addr.sun_path) - 1);
        if (bind(server_fd, (struct sockaddr*)&addr, sizeof(addr)) < 0) {
            perror("bind");
            close(server_fd);
            return;
        }
        if (listen(server_fd, 5) < 0) {
            perror("listen");
            close(server_fd);
            return;
        }
        ROBOT_INFO("[Daemon] SocketServer listening on {}.", socket_path_);
        while (daemon_running_.load()) {
            int client_fd = accept(server_fd, nullptr, nullptr);
            // 具体服务端逻辑实现
            // ......
            close(client_fd);
        }
        close(server_fd);
        unlink(socket_path_.c_str());
        ROBOT_INFO("[Daemon] SocketServer stopped.");
        return;
    }

bool ChangeMode(const std::string& body) {
        try {
            auto json_body = nlohmann::json::parse(body);
            auto mode = json_body["mode"];

            switch (mode_.load()) {
                case robot::common::RobotMode::Damping:
                    if (robot::common::DAMPING_PATH.find(mode) == robot::common::DAMPING_PATH.end()) {
                        return false;
                    }
                    break;
                case robot::common::RobotMode::Prepare:
                    if (robot::common::PREPARE_PATH.find(mode) == robot::common::PREPARE_PATH.end()) {
                        return false;
                    }
                    break;
                case robot::common::RobotMode::Walking:
                    if (robot::common::WALKING_PATH.find(mode) == robot::common::WALKING_PATH.end()) {
                        return false;
                    }
                    break;
                case robot::common::RobotMode::Custom:
                    if (robot::common::CUSTOM_PATH.find(mode) == robot::common::CUSTOM_PATH.end()) {
                        return false;
                    }
                    break;
                default:
                    return false;
            }
            mode_.store(mode);
        } catch (const std::exception& e) {
            ROBOT_ERROR("Paser json Error: {}\n", e.what());
            return false;
        }
        return true;
    }

总结#

优点：

  • 小机器人的后台程序，是来对所有的硬件、通讯、服务进行统一管理的程序，当前方案有助于机器人复用上述模块，达到快速简单实现一个类似的机器人后台管理程序。
  • 这个方案的主要优势是高模块化与解耦 DDS 中间件，可以使得硬件控制、上层逻辑和通讯可以完全分离。每个部分都可以独立进行单元测试和集成测试。
  • 采用了业界主流的技术栈（CMake，C++/Python， DDS）。

对比主流方案（产品）目前缺少：

  • WebRTC（远程控制与媒体流）、gRPC功能（用于远端进行RPC）
  • GStreamer（视频编码、转码），RTSP/WebRTC 统一媒体流接口
  • 缺乏 OTA（固件/软件升级）能力，无法远程升级，软件更新需要人工干预，无回滚机制。
