# 像侦探一样排查问题


--

调试的产物不只是“现在好了”，还包括：问题如何触发、为什么发生、什么证据支持修复。

----
## 第一步：保留现场


--

- 保存输入、完整报错、日志中的时间与版本。

--

- 记录期待结果和实际结果。

--

- 区分稳定复现、偶发、仅特定环境发生。

--

- 先保留失败证据，再尝试修改。


--

“程序有时候崩溃”可改成：“输入空列表后，`average` 在除法处抛出异常；三次均可复现。”

----
## 第二步：缩小复现


--

把真实输入缩减到仍能触发错误的最小输入。


--

```python
def average(values):
    return sum(values) / len(values)

print(average([]))  # ZeroDivisionError
```


--

删除数据库、界面和网络之后仍会失败，调查就应先聚焦输入契约与空列表处理。


--

最小复现不是随便换一个错误：要确认错误类型与触发机制仍然一致。

----
## 第三步：先列假设，再动手


--

| 假设 | 能区分它的检查 |
|---|---|
| 空输入没有定义 | 检查接口说明和调用方 |
| 过滤后恰好为空 | 记录过滤前后元素数量 |
| 数据源暂时无数据 | 用固定非空输入替换来源 |


--

每次实验尽量只改变一件事，并记录结果。
随手同时改三个条件，即使恢复正常也难以知道是哪一项生效。

----
## 第四步：沿边界找错误


--

检查数据经过的边界：采集 → 解析 → 过滤 → 计算 → 展示。


--

- 打印结构与数量，而不是无差别输出全部数据。

--

- 用断点观察失败前的变量值。

--

- 如果旧版本正常，用版本二分缩小引入范围。

--

- 并发问题记录线程、事件顺序与时间；加日志本身也可能改变时序。


--

崩溃发生的位置，可能只是上游错误第一次变得可见的地方。

----
## 第五步：按契约修复


--

本例约定：平均值只接受非空序列，空输入给出明确错误。


--

```python
def average(values):
    if not values:
        raise ValueError('average requires non-empty input')
    return sum(values) / len(values)

assert average([2, 4, 6]) == 4
assert average([-3]) == -3
try:
    average([])
except ValueError as error:
    assert 'non-empty' in str(error)
else:
    raise AssertionError('empty input must fail')
```


--

返回 `0` 会把“没有数据”伪装成有效测量，只有契约明确这样定义时才能采用。

----
## 第六步：防止问题回来


--

把最小失败输入加入测试，再检查相邻边界。


--

修复记录应包含：触发条件、根因、改变的行为、验证方式。


--

```text
触发：过滤后无有效样本。
根因：调用方没有处理空序列，计算函数也未检查。
修复：计算函数显式拒绝空序列，界面显示“暂无数据”。
验证：空、单个、正负混合样本，以及过滤后的调用链。
```

----
## 练习与答案


--

“重启后恢复正常”证明了什么？


--

**答案**：重启改变了状态，说明内存、连接、缓存或外部时序可能参与；尚不能证明根因是内存泄漏。


--

下一次故障前后记录内存趋势、连接数与输入；设计能够区分候选原因的检查。


--

参考：[Python 异常处理](https://docs.python.org/3/tutorial/errors.html)、[Git bisect](https://git-scm.com/docs/git-bisect)。
