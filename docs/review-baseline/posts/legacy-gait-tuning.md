这是 2023 年的笔记，当时的做法是**手调 CPG 参数 + 试错**，没有 MPC/WBC 分层。现在项目里已经换成 MPC + WBC，这篇的具体参数不再适用。保留是因为里面记录的机械与标定问题仍然会出现。

## 当时的平台

- 12 自由度，每条腿 3 个关节（外展 / 髋 / 膝）
- 关节驱动：准直驱电机 + 谐波减速器
- 控制器：单板 ARM，控制周期 1 kHz
- 无足底力传感器，只有关节电流估算

## Trot 步态的基本参数

| 参数 | 初值 | 最终值 | 说明 |
|---|---:|---:|---|
| 步态周期 | 0.4 s | 0.32 s | 太快会失稳，太慢会晃 |
| 支撑相占比 | 0.5 | 0.55 | 略大于 0.5 更稳 |
| 抬腿高度 | 0.08 m | 0.06 m | 高了落地冲击大 |
| 身体高度 | 0.28 m | 0.26 m | 降低质心明显更稳 |
| 摆动相轨迹 | 正弦 | 三次样条 | 落地速度可控 |

## 踩过的坑

::: warn 归档前记下的问题，现在仍然会遇到
1. **零位标定不一致**。四条腿的关节零位差 1~2°，走路会往一边偏。必须用机械限位逐个标，不能靠编码器上电值。
2. **足端接触判定用电流阈值不可靠**。电流受温度影响很大，跑十分钟阈值就漂了。后来换成"电流 + 关节速度突降"双条件。
3. **减速器回差**。谐波减速器空程 1~2 arcmin，在小幅摆动时表现为末端"空走一段"。柔顺控制必须考虑，否则位置环会积分到振荡。
4. **电池电压下降导致力矩不足**。满电和低电时同样的电流指令，输出力矩差 20%。后来加了电压前馈补偿。
5. **腿长不对称**。装配误差导致四条腿实际长度差 3~5 mm，站着就不平。用身体高度偏差补偿掉了。
:::

## 当时的步态代码

```python
def trot_trajectory(phase, cycle=0.32, stride=0.12, height=0.06, duty=0.55):
    """相位 0-1 -> 足端相对髋的位置 (x, z)"""
    if phase < duty:                      # 支撑相：向后推
        s = phase / duty
        x = stride * (0.5 - s)
        z = 0.0
    else:                                 # 摆动相：抬起前摆
        s = (phase - duty) / (1 - duty)
        x = stride * (s - 0.5)
        z = height * math.sin(math.pi * s)
    return x, z
```

## 后来怎么被替代的

这套方案的极限很清楚：**没有力分配，靠位置硬撑**。侧向推力超过 60 N 就会失稳，斜坡超过 8° 就打滑。

换成 MPC + WBC 之后（见 [四足运控：MPC 与 WBC 的分层结构](/posts/quadruped-mpc-wbc/)），同样的硬件侧向推力能扛到 210 N，20° 斜坡无压力。根本区别是接触力变成了决策变量，而不是位置环的副产品。
