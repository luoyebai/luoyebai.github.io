你以为 shell 是个「程序」，其实它只是一个循环。

1. 命令行里到底发生了什么

你在终端敲下 ls -l /tmp 的那一瞬间

系统里发生了这些事，而没有任何一步是魔法：

  • 终端把按键交给 shell 进程
  • shell 读到一行，按空格切成几个词
  • shell 判断：ls 不是我的内建命令 → 我得造一个子进程去跑它
  • 子进程把自己换成 ls 这个程序
  • 父进程（shell）等着，直到子进程结束
  • 打印下一个提示符，回到第一步

一句话概括

shell 的全部工作就是：读一行、切词、造进程、等它结束、重复。

  • 「变成一门语言」的那些东西（变量、引号、通配符、管道）都是在这个循环上长出来的。
  • 所以你想真正理解它，最好的方式是自己写一个最小的。

这也是为什么这一节的代码只有几十行 —— 骨架不长，长的是边角。

2. 一个最小可用的骨架

二十行，能跑命令

c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
#include <string.h>

int main(void) {
    char line[1024];
    while (1) {
        printf("mini_sh> ");                       /* 1. 提示符 */
        fflush(stdout);
        if (!fgets(line, sizeof line, stdin)) break; /* 2. 读一行 */
        line[strcspn(line, "\n")] = 0;             /*    去掉换行 */

        char *argv[64] = {0};
        int argc = 0;                              /* 3. 切词 */
        for (char *p = strtok(line, " "); p && argc < 63; p = strtok(NULL, " "))
            argv[argc++] = p;
        if (argc == 0) continue;

        pid_t pid = fork();                        /* 4. 造子进程 */
        if (pid == 0) {
            execvp(argv[0], argv);                 /*    子进程：换程序 */
            perror("exec");                        /*    换失败才会走到这 */
            _exit(127);
        }
        int status;
        waitpid(pid, &status, 0);                  /* 5. 父进程：等 */
    }
    return 0;
}
  • 这二十行已经能跑 ls、cat、gcc 了。剩下的全是边角。

切词这一步比看上去难

新手会以为「按空格切」就够了，实际上一行 shell 输入要先过这些：

输入你以为的切法实际规则
echo "a b"echo / "a / b"引号内的空格不算分隔
echo 'a b'同上单引号里什么都不解释
echo $HOME字面量先做变量展开
echo *.c字面量先做通配符展开
echo a\|b三个词\| 是管道，不是普通字符

顺序也不能换：切词 → 引号处理 → 展开 → 再切管道。
换一下顺序，echo "a | b" 就会被当成管道。

试一个：自己写个分词器

下面这段是可运行的 —— 它做的正是 shell 的第一步。 试着改一改：让它支持单引号，或者让它把 | 单独切出来。

可运行示例JavaScript
// 一个最小分词器：处理空格、双引号、反斜杠转义
function tokenize(line) {
  const out = [];
  let buf = '', quote = false, i = 0;
  while (i < line.length) {
    const c = line[i];
    if (quote) {
      if (c === '\\' && i + 1 < line.length) { buf += line[++i]; i++; continue; }
      if (c === '"') { quote = false; i++; continue; }
      buf += c; i++; continue;
    }
    if (c === '"') { quote = true; i++; continue; }
    if (c === '\\' && i + 1 < line.length) { buf += line[++i]; i++; continue; }
    if (c === ' ' || c === '\t') {
      if (buf) { out.push(buf); buf = ''; }
      i++; continue;
    }
    buf += c; i++;
  }
  if (buf) out.push(buf);
  return { tokens: out, closed: !quote };
}

const cases = [
  'ls -l /tmp',
  'echo "a  b" -n',
  'grep "x \\" y" file.c',
  'echo "没关引号',
];
for (const s of cases) {
  const r = tokenize(s);
  demo.log('输入:', s);
  demo.log('  →  ', JSON.stringify(r.tokens), r.closed ? '' : '⚠ 引号没闭合');
}

注意最后一条：真实的 shell 遇到没闭合的引号会再要一行， 而不是硬着头皮执行。这就是「交互式」和「批处理」的区别。

3. 管道、重定向、内建命令

管道：一条内核缓冲区 + 两个文件描述符

ls | grep c 里的 | 不是把命令串起来，而是造了一根管子。

实现顺序很固定：

  • 父进程 pipe(fd) —— 拿到读写两端
  • fork 两次，得到左右两个孩子
  • 左孩子在 exec 之前 dup2(fd[1], 1)，把 stdout 接到写端
  • 右孩子在 exec 之前 dup2(fd[0], 0)，把 stdin 接到读端
  • 两边都把自己的 fd 关掉，wait 收尸

顺序错了就死锁：忘了在父进程里关掉 fd，读端永远等不到 EOF。

重定向其实就是改文件描述符

  • > file：open(file, O_WRONLY|O_CREAT|O_TRUNC) 之后 dup2(fd, 1)。
  • < file：同理 dup2(fd, 0)。
  • 2>&1：把 fd 2 也指到 fd 1 现在指的地方 —— 注意是「现在」。
shell
# 这两条不一样，顺序有意义
cmd > out.txt 2>&1     # stdout 和 stderr 都进 out.txt
cmd 2>&1 > out.txt     # stderr 进终端，stdout 进文件

cd 为什么不能是外部程序

这是 shell 设计里最漂亮的一处约束：

  • 每个进程有自己的「当前工作目录」，它是进程的属性。
  • cd 如果是外部程序，它跑在子进程里，改的是子进程的目录。
  • 子进程一退出，改动就没了，父进程（shell）的工作目录纹丝不动。

所以 cd 必须是内建命令。
同样必须是内建的还有：export、alias、umask、jobs、fg、bg —— 它们改的都是 shell 进程自己的状态。

判断标准很简单：这条命令有没有副作用落在「当前这个 shell」身上。

前台、后台与信号

  • & 让子进程进后台，shell 不 wait 它，直接打印下一个提示符。
  • 但 shell 不能不管它 —— 它在作业表里记着，jobs 能查、fg 能捞回来。
  • Ctrl+C 不是 shell 处理的，是终端把 SIGINT 发给前台进程组。 shell 自己也要处理这个信号，否则一按就把自己杀了。
text
你想清楚三件事，mini shell 就完整了：
  1) 谁是前台进程组
  2) 谁负责 wait
  3) 信号发给谁

4. 源码怎么读

从最小到完整

文件做什么大概多少行
mini_sh.c只有循环 + fork/exec几十行
sh-xv6.c加了重定向、管道、内建命令三百行左右
test.c测试用例—
  • 读的顺序：先读 mini_sh.c 把主干记住，再读 sh-xv6.c 看它补了哪些边角。
  • 不要从头读到尾 —— 先找 fork、exec、wait 这三个词， 把主干抽出来，剩下的都是分支。

小结

  1. shell 是一个循环：读 → 切词 → fork → exec → wait。
  2. 切词的顺序不能换，引号要先于管道。
  3. 管道是内核缓冲区 + dup2；重定向本质是改文件描述符。
  4. 内建命令之所以内建，是因为它们要改 shell 自己的状态。

写完你会对所有「命令行」祛魅。
然后你会发现，祛魅之后反而更好用。
