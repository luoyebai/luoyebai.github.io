Q1. 为什么第一门语言是它？

先问一句：第一门语言学什么，真的重要吗

  • 重要，但没有你想的那么重要。
  • 真正难的是「把一个想法拆成步骤」，这件事换哪种语言都一样。
  • 所以第一门语言的任务只有一条：让你尽可能快地把想法跑起来， 而不是让你一次学完所有概念。
  • 那为什么不从 C 开始？——C 会逼你同时面对三件事：
  1. 语言本身
  2. 内存与地址
  3. 编译、链接、构建

新手同时接三个球，基本都会掉。

Python 把哪些东西先替你收起来了

你暂时不用管什么时候再回来管
类型声明想写大一点的项目时
手动管内存需要抠性能时（先学会 C）
编译链接需要发布成单文件时
工程结构代码超过几百行时

先能跑，再谈好。 这句话对新手和对老手都成立，只是「好」的标准不同。

顺手说清楚：Python 慢，是不是问题

  • 是，也不是。
  • 纯 Python 的循环确实比 C 慢一到两个数量级，这是事实。
  • 但工程里真正的瓶颈往往不在语言，而在算法和数据搬运。
  • 而且 Python 的生态里，吃性能的那部分（numpy / OpenCV / PyTorch） 本来就是 C/C++ 写的，Python 只是那个「遥控器」。
text
你用 Python 描述「要算什么」，
真正在算的是下面那层 C —— 所以速度未必差。

ps：真到了遥控器也不够用的时候，再回去学 C 和指针，那时候你会有明确的目标。

Q2. Python 到底是什么？

一句话：它是一种解释型的、动态类型的语言

拆开看这两个词：

  • 解释型 —— 没有「编译成机器码」这一步独立的产物， 代码交给一个叫解释器的程序，它一边读一边执行。
  • 动态类型 —— 变量不声明类型，类型跟着它当时指向的那个对象走。
  • 这两条决定了后面所有的行为，包括那些让人困惑的报错。

「名字」和「对象」是两回事

这是新手到进阶最重要的一道坎。

  • a = [1, 2, 3] 做的是：先造一个 list 对象，再把名字 a 绑到它上面。
  • b = a 做的是：把 b 也绑到同一个对象上。
  • 所以改 b 就是改 a —— 它们不是两个盒子，是两个标签贴在同一个盒子上。
python
a = [1, 2, 3]
b = a
b.append(4)
print(a)          # [1, 2, 3, 4]  —— a 也变了

c = list(a)       # 这才是复制
c.append(5)
print(a)          # [1, 2, 3, 4]

那些「奇怪」的报错都从这来

TypeError: 'NoneType' object is not subscriptable
你拿到的不是你想的那个东西。多数情况是某个函数忘了写 return。

UnboundLocalError: local variable 'x' referenced before assignment
函数里给 x 赋过值 → Python 就认为整个函数里 x 都是局部的， 函数开头那次读取就撞上了「还没绑」。

ValueError: too many values to unpack
右边的对象和你左边写的名字个数对不上。数一数就行。

看 Python 的报错要从最后一行往回读。 最后一行是「发生了什么」，往上几行是「在哪发生」。

Q3. 从哪一行开始？

环境：先把这个坑填了

新手 90% 的「装不上」都出在这里。

方案适合说明
官网安装包 + python -m venv推荐一个项目一个虚拟环境，干净
conda / miniconda做科学计算能装非 Python 的依赖（CUDA 之类）
系统自带的 python3只写脚本别往里装东西，系统工具依赖它
bash
# 一个项目一个环境，这是纪律不是建议
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate      # Linux / macOS

pip install numpy              # 装完记得 freeze 下来
pip freeze > requirements.txt

一个脚本 → 一个模块 → 一个包

不要一上来就搭目录结构。

python
# 1) 先是一个脚本：直接跑
def area(r):
    return 3.14159 * r * r

print(area(2))
python
# 2) 想复用的时候，加一个入口判断 —— 它才是「模块」
def area(r):
    return 3.14159 * r * r

if __name__ == '__main__':
    print(area(2))
text
3) 文件多了再拆目录 + __init__.py，那才叫包。
   顺序反了的话，你会花一整天在设计目录，而不是在写代码。

if __name__ == '__main__': 的含义：「这个文件是被直接运行的，而不是被 import 的」。 被 import 时 __name__ 是模块名，所以这段不会执行。

新手一定会踩的五个坑

  • 可变默认参数：def f(x, acc=[]) —— 那个 [] 只造一次，会跨调用累积。
python
def bad(x, acc=[]):        # 别这么写
    acc.append(x)
    return acc

def good(x, acc=None):
    acc = [] if acc is None else acc
    acc.append(x)
    return acc
  • 浮点数：0.1 + 0.2 != 0.3。要精确就用 decimal，要比较就用 abs(a-b) < eps。
  • 缩进是语法：混用 Tab 和空格会报错，选一个，然后让编辑器替你统一。
  • is 和 ==：is 比的是「是不是同一个对象」，比数值请用 ==。 小整数和短字符串会被缓存，所以 is 有时「看起来能用」—— 那是假象。
  • 忘了激活虚拟环境：装到了系统 Python 里，然后奇怪为什么 import 不到。

小结

三句话

  1. 第一门语言的任务是让你快跑起来，Python 干这个最合适。
  2. 它的两个关键词是解释执行和动态类型，记住 「名字」和「对象」是两回事，一大半困惑就没了。
  3. 先把环境弄干净（虚拟环境），再从一个脚本开始长，别提前设计目录。

真到了「遥控器不够快」的那天，再回来看 从指针来理解程序的执行 —— 那时候你会带着具体的问题去读，效率完全不一样。

动手

  • 装一个 Python，建一个虚拟环境，写一个只有 10 行的脚本。
  • 用 print() 和报错信息对话，别怕它。
  • 明天再去看 编程概述 里的「Q3 如何编程」， 你会发现那些抽象的话现在有落脚点了。
