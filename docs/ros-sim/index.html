Q1. 仿真到底解决什么问题

先排除一个错误答案

「仿真跑通了，真机就差不多了。」

这句话是错的，而且是很多人第一次做 sim2real 时最贵的一课。 那仿真还值得做吗？值得，因为它解决的是另外四件事：

  • 不用等硬件：机械臂还在采购，控制器的代码可以先写。
  • 不会摔坏：调参数时炸一百次，代价是零。
  • 可以复现：同一段轨迹能一模一样地重放，这在真机上做不到。
  • 能加速：仿真可以跑得比实时快，采数据用得上。

仿真的价值在「迭代速度」，不在「真实性」。

什么时候不值得上仿真

  • 只做一次、路径很短的验证 —— 搭环境的成本比直接上真机高。
  • 瓶颈在接触（装配、插拔、拧螺丝）—— 现在的接触仿真还不便宜也不够准。
  • 瓶颈在感知（光照、反光、透明件）—— 渲染差距会把结论带偏。

还有一种：只是想截一张好看的图发朋友圈。

Q2. 选哪个仿真器

对照表

Gazebo / IgnitionMuJoCoIsaac SimPyBullet
定位ROS 原生仿真接触与动力学GPU 大规模并行轻量快速
物理精度中高（接触）中高中
渲染中弱强（光追）弱
速度实时快极快（几千环境并行）快
ROS 集成最好一般好一般
上手成本低低高（要 GPU）最低
适合系统联调足式 / 操作臂控制强化学习 / 合成数据算法原型

怎么选：看你要验证什么

  • 验证系统集成（话题通不通、launch 写得对不对）→ Gazebo。
  • 验证控制器（WBC / MPC 跟不跟得上）→ MuJoCo。
  • 训练强化学习策略、需要几百万步 → Isaac Sim。
  • 只是想快速试一个算法 → PyBullet。

选错仿真器的代价不是「跑不起来」，而是「结论不可信」。 用渲染很弱的仿真器去研究视觉，得出来的结论没有意义。

仿真循环里有个必须守的规矩

物理步进必须是定步长。

  • 物理引擎的稳定性、接触求解、积分误差全都建立在「每步 dt 固定」之上。
  • 用真实时间当 dt，帧率一抖，机器人就会自己抖起来 —— 而且现象像是控制器的问题。
text
墙上的钟  → 真实时间（Real Time Factor 描述仿真比它快还是慢）
仿真时钟  → 仿真器自己数的时间，控制器应该用它

仿真里要把 use_sim_time 打开，否则节点用真实时间， 一加速仿真，所有定时器都会错乱。

Q3. URDF 怎么写

一棵树，两种东西

  • link：刚体。有质量、惯性矩阵、可视几何、碰撞几何。
  • joint：连接父子 link。描述「绕哪根轴、什么类型、限位多少」。

关节类型只有这几种，别记混：

类型自由度用途
fixed0传感器固定安装
revolute1，有限位机械臂关节
continuous1，无限位轮子
prismatic1，直线升降、夹爪
floating6浮动基座
planar2平面移动

一个最小可用的 URDF

xml
<robot name="arm">
  <link name="base_link">
    <inertial>
      <mass value="5.0"/>
      <inertia ixx="0.02" iyy="0.02" izz="0.03" ixy="0" ixz="0" iyz="0"/>
    </inertial>
    <visual>
      <geometry><cylinder radius="0.1" length="0.2"/></geometry>
    </visual>
    <collision>
      <geometry><cylinder radius="0.1" length="0.2"/></geometry>
    </collision>
  </link>

  <link name="upper_arm"/>

  <joint name="shoulder" type="revolute">
    <parent link="base_link"/>
    <child link="upper_arm"/>
    <origin xyz="0 0 0.15" rpy="0 0 0"/>   <!-- 相对父 link 的位置 -->
    <axis xyz="0 1 0"/>                    <!-- 绕 y 轴转 -->
    <limit lower="-1.57" upper="1.57" effort="50" velocity="3.0"/>
  </joint>
</robot>

最容易写错的四处：质量的量级、惯性矩阵、 origin 的坐标系（是父 link 的）、以及碰撞几何比可视几何大一圈。

Xacro：别手写 URDF

真机模型几百行，直接写 URDF 会疯。Xacro 是它的宏语言：

xml
<xacro:macro name="wheel" params="prefix reflect">
  <link name="${prefix}_wheel"/>
  <joint name="${prefix}_wheel_joint" type="continuous">
    <parent link="base_link"/>
    <child link="${prefix}_wheel"/>
    <origin xyz="0 ${0.15 * reflect} -0.05" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
  </joint>
</xacro:macro>

<xacro:wheel prefix="left"  reflect="1"/>
<xacro:wheel prefix="right" reflect="-1"/>
  • 左右对称的部件写一次就够。
  • 参数、常量、条件、<xacro:include> 都能用。
  • 改完记得 xacro robot.urdf.xacro > robot.urdf 再检查。

检查模型的两个土办法

  1. 看重心：rviz2 里打开 TF 和模型，如果机器人一加载就往下掉或者抖， 多半是质量或惯性矩阵写错了。
  2. 数质量：check_urdf robot.urdf 加总质量，和实物称出来的对一下。 差得离谱就说明单位写错了（kg？g？mm？m？）。

ps：CAD 导出的模型经常是 mm + g，直接丢进仿真会得到一个重一千倍的机器人。

Q4. 为什么到真机就不灵了

差距在哪

sim2real gap 不是「仿真不够真」这么笼统，它是具体的几项：

  • 接触参数：摩擦系数、恢复系数、接触刚度 —— 最难测，也最敏感。
  • 延迟：仿真的电机是瞬时的，真机有 5~20 ms 的响应延迟。
  • 传感噪声：真机的 IMU 有偏置和温漂，编码器有量化误差。
  • 未建模动态：线缆、背隙、柔性、气动。
  • 视觉域差：光照、镜头畸变、运动模糊、材质反射。

三种应对

手段做法适合
域随机化训练时把上面几项随机扰动，让策略见过足够宽的分布强化学习
系统辨识用真机数据拟合仿真参数，把 gap 本身调小经典控制
在线自适应策略/控制器自己估计并补偿两者结合
  • 域随机化的关键不是「随机」，而是随机区间要和真机对得上。
  • 区间太宽 → 策略变得保守、动作发软；太窄 → 一上真机就出分布。

先量真机，再定区间。这一步省不掉。

一条实用的验收线

在相信仿真结论之前，先做这件事：

  1. 在真机上跑一条固定的轨迹，录下关节指令与实际状态。
  2. 在仿真里回放同样的指令，录下仿真状态。
  3. 把两条曲线画在一起，看相位差和幅值差。
  • 相位差 → 延迟没建模；幅值差 → 摩擦/惯量不对。
  • 两条曲线对不上的话，仿真里调出来的参数一个字都别信。

小结

  1. 仿真买的是迭代速度，不是真实性。
  2. 选仿真器要看你要验证什么，选错了结论不可信。
  3. 物理必须定步长，仿真里记得开 use_sim_time。
  4. URDF 是一棵树；质量/惯性/origin 是三个高频错误点。
  5. sim2real 的差距是具体的几项参数，先量真机再定随机区间。
