从 C 语言到 C++ 的转变

C++ 不是「带类的 C」。从过程式到泛型，先看清楚它到底补了 C 的哪几个洞，再决定哪些特性值得用。

这篇不教语法。语法书到处都是，这里只讲「为什么要变」。

Q1. C 的边界在哪？

C 的假设：你自己管好一切

C 是一门贴着机器的语言，它的每一条设计都在说同一句话：

「我不管你，你自己清楚你在干什么。」

  • 内存：malloc / free，配对是你的事。
  • 资源：文件、锁、socket，关不关是你的事。
  • 类型：能隐式转换就转，转错了也不拦你。
  • 错误：多数函数只返回一个数，含义靠约定。

这套设计带来了极致的可控和可预测 —— 也带来了所有错误都得靠人记。

于是有了这三类经典 bug

类型长什么样根因
资源泄漏提前 return、中途抛错，fclose 没走到释放点分散在多个出口
悬垂指针free(p) 之后又用 p指针和它的生命周期脱钩
重复释放 / 未初始化有时崩，有时不崩状态靠人脑维护
  • 注意第二列：它们都不是「写错了」，而是「忘了写」。
  • 编译器不会因为你少写一行就报错。所以它们能活到线上。

真的没有办法吗

  • 有，而且 C 程序员一直在用 —— 只是要靠纪律：
c
int load(const char *path, char **out) {
    FILE *f = fopen(path, "rb");
    if (!f) return -1;
    long n = filesize(f);
    char *buf = malloc(n);
    if (!buf) { fclose(f); return -2; }     /* ← 每个出口都得记得 */
    if (fread(buf, 1, n, f) != (size_t)n) {
        free(buf); fclose(f); return -3;    /* ← 又是两行 */
    }
    fclose(f);
    *out = buf;
    return 0;
}
  • 这段代码没错。但它有 4 个出口，每个都要写对。
  • 加一个「出错时打日志」的需求，就要改 4 处。

C++ 想做的，就是把「记得」交给类型系统。

Q2. C++ 补了哪几个洞？

洞一：让「释放」跟着「作用域」走 —— RAII

RAII = Resource Acquisition Is Initialization，直译很绕，意思是：

把资源的生命周期绑到一个对象的生命周期上。

cpp
int load(const std::string &path, std::vector<char> &out) {
    std::ifstream f(path, std::ios::binary);   // 构造即打开
    if (!f) return -1;
    out.assign(std::istreambuf_iterator<char>(f), {});
    return 0;                                   // 离开作用域，自动关闭
}
  • 没有一处 close，也没有一个出口需要特别处理。
  • 中途抛异常也一样会关 —— 这是 C 里做不到的。

洞二：值语义与引用，把「拷贝」说清楚

  • C 里所有东西都是值，想要「别名」只能传指针 —— 然后指针可以为 NULL、 可以指向已经死掉的对象。
  • C++ 把三件事分开表达了：
写法含义可不可以为空
void f(T x)我拿走一份拷贝不适用
void f(T &x)我要改你不可以（必须传对象）
void f(const T &x)我只读，且不想拷贝不可以
void f(T *x)可能没有可以

函数签名本身就成了文档。看到 const T& 你就知道它不会改你、也不会拷你。

洞三：泛型 —— 同一种算法只写一遍

C 里想对 int 和 double 各写一份排序，只能靠宏或者复制粘贴。

c
/* C 的宏版本：能跑，但报错信息基本没法看 */
#define MAX(a, b) ((a) > (b) ? (a) : (b))
MAX(i++, j++)      /* ← 自增了两次 */
cpp
// C++ 的模板版本：类型是参数，报错能定位到具体类型
template <class T>
const T &maxOf(const T &a, const T &b) { return a > b ? a : b; }
  • 模板是编译期展开的，所以没有运行时开销。
  • 代价是编译变慢、报错变长 —— 这是后面要单独讲的一节。

Q3. 哪些特性值得用？

优先级清单

先按这个顺序用，其余的先不碰：

  1. RAII：std::string、std::vector、std::ifstream、智能指针。
  2. 引用与 const：把所有「不该改」的地方标出来。
  3. STL 容器与算法：别自己写链表和排序。
  4. 模板：只在真的需要「同一套逻辑多种类型」时用。
  5. 继承与虚函数：用于接口，不用于复用实现。

反过来说：不要因为「C++ 有」就去用。
多继承、运算符重载、异常规格、裸 new/delete —— 先当它们不存在。

STL：容器、迭代器、算法

这是 C++ 最值钱的部分，也是「不像 C」的部分。

cpp
#include <algorithm>
#include <vector>

std::vector<int> v{5, 2, 9, 1};
std::sort(v.begin(), v.end());                       // 1 2 5 9

// 迭代器把「容器」和「算法」解耦了：
// sort 不知道 v 是 vector 还是数组，它只要一对迭代器
int a[] = {3, 1, 2};
std::sort(std::begin(a), std::end(a));
  • 算法不关心容器，这是泛型编程的核心收益。
  • 记住三个动词：begin / end 划范围，算法吃这个范围。

智能指针：把所有权说清楚

cpp
#include <memory>

auto p = std::make_unique<Widget>();        // 独占：不能拷贝，只能移动
auto q = std::make_shared<Widget>();        // 共享：引用计数归零才释放

std::weak_ptr<Widget> w = q;                // 观察：不增加计数，打破循环引用
  • unique_ptr 应该是默认选择 —— 它零开销，且表达了「只有一个主人」。
  • 只有真的需要共享所有权时才上 shared_ptr，因为引用计数有成本。
  • 一旦用了智能指针，裸 new 就不应该出现在业务代码里。

现代 C++ 值得记住的几条

特性版本一句话
autoC++11让编译器推类型，别手写一长串
range-forC++11for (auto &x : v)，不用再写迭代器
移动语义C++11std::move 把资源搬走，不拷贝
nullptrC++11替换 NULL，类型安全
constexprC++11/14能在编译期算的就别留到运行期
结构化绑定C++17auto [k, v] = pair;
std::optionalC++17「可能没有值」写进类型
概念 conceptsC++20给模板参数加约束，报错终于能看了

别一次全用。把 RAII、const、STL 这三样用熟，你就已经写得比大多数「C with class」好了。

最后一句劝告

不要把 C++ 写成「带类的 C」。

  • 还是手工 malloc/free、还是到处裸指针、还是自己写数组循环 —— 那就等于付了 C++ 的复杂度，却没拿到它的好处。
  • 反过来也一样：不要在 C 里假装有 C++。 用 C 写嵌入式、写内核模块，就老老实实按 C 的纪律来。

语言是工具。先问「我要解决什么问题」，再问「这门语言为此提供了什么」。

小结

  1. C 的边界是「所有清理都得靠人记」，RAII 把这件事交给了作用域。
  2. 引用 + const 让函数签名本身说明「会不会改你」。
  3. 模板与 STL 让算法只写一遍，且没有运行时开销。
  4. 用法上要有优先级：RAII → const → STL → 模板 → 继承，别倒过来。
