Q1. 一张图在计算机里是什么

三维数组，仅此而已

  • 彩色图 = 高 × 宽 × 通道 的三维数组，每个数 0~255。
  • 灰度图就是通道数为 1 的情况。
  • 「图像处理」= 对这个数组做各种运算；「计算机视觉」= 从运算结果里读出含义。
python
import cv2
img = cv2.imread('face.jpg')
print(img.shape)        # (480, 640, 3)  → H, W, C
print(img[100, 200])    # [B, G, R] 三个数，就是那一个像素

三个必须记住的坑

1. OpenCV 是 BGR，不是 RGB。
cv2.imread 读进来通道顺序是 B-G-R，而 matplotlib / PIL 是 R-G-B。 直接互传会得到一张红蓝互换的图 —— 人脸会变得很吓人。

python
rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
plt.imshow(rgb)

2. 坐标是 img[y, x]，不是 img[x, y]。
先横后竖是数学，先行后列是矩阵。OpenCV 站在矩阵那边。

3. 尺寸是 (宽, 高)，但 shape 是 (高, 宽, 通道)。
cv2.resize(img, (640, 480)) 里的 640 是宽。

灰度化：为什么第一步总是它

  • 颜色对「这是不是一张脸」几乎没有帮助，但对计算量影响很大：数据量降到 1/3。
  • 最朴素的灰度化是加权平均 —— 人眼对绿色最敏感，所以权重不同：
text
gray = 0.299·R + 0.587·G + 0.114·B
  • 这不是随便取的系数，是当年从人眼亮度响应曲线上量出来的。

试一个：把一张图画成灰度

下面这段直接操作像素，把「灰度化 + 阈值」在浏览器里跑出来。 改改阈值，看看二值化之后还剩多少信息。

可运行示例JavaScript
// 造一张 12x12 的“图”，中间画一个亮方块充当“脸”
const W = 12, H = 12;
const img = [];
for (let y = 0; y < H; y++) {
  const row = [];
  for (let x = 0; x < W; x++) {
    const inFace = x >= 3 && x <= 8 && y >= 2 && y <= 9;
    const edge = (x === 3 || x === 8 || y === 2 || y === 9) && inFace;
    row.push(edge ? [40, 42, 48] : inFace ? [220, 205, 190] : [70, 80, 95]);  // 假装是 BGR
  }
  img.push(row);
}

const toGray = ([b, g, r]) => Math.round(0.114 * b + 0.587 * g + 0.299 * r);
const gray = img.map(row => row.map(toGray));

const art = (arr, fmt) => arr.map(row => row.map(fmt).join('')).join('\n');
const ramp = v => ' .:-=+*#%@'[Math.min(9, Math.floor(v / 25.6))];
demo.log('灰度图（越亮字符越密）：');
demo.log(art(gray, v => ramp(v)));

for (const t of [100, 150, 180]) {
  demo.log('');
  demo.log('二值化，阈值 ' + t + '：');
  demo.log(art(gray, v => (v > t ? '█' : '·')));
}
demo.log('');
demo.log('阈值 100 时脸和背景都还在；到 180，背景被抹平，只剩脸最亮的那块。');

阈值这个数字不是拍出来的，要看直方图。

Q2. OpenCV 怎么用

它是什么

  • OpenCV 是一个用 C++ 写的图像处理库，Python 只是它的一个绑定。
  • 所以：调用开销小、底层是优化过的、但接口风格很 C（到处是 dst= 参数）。
bash
pip install opencv-python          # 主包
pip install opencv-contrib-python  # 含 SIFT、人脸模块等额外算法

命名空间是 cv2 而不是 cv，那是历史原因（第一版是 C 的 cv）。

五个函数够你起步

python
import cv2

img = cv2.imread('in.jpg')                       # 读
h, w = img.shape[:2]
img = cv2.resize(img, (w // 2, h // 2))          # 缩
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)     # 转灰度
blur = cv2.GaussianBlur(gray, (5, 5), 0)         # 去噪
edges = cv2.Canny(blur, 80, 160)                 # 找边缘
cv2.imwrite('out.png', edges)                    # 写
  • imread 读不到文件时不报错，返回 None。 所以下一行报 'NoneType' has no attribute，其实错在上一行。

卷积：图像处理里唯一的那个动作

  • 模糊、锐化、边缘检测，全都是「换一个核」。
  • 3×3 的核在图上滑动，每个位置做加权求和 —— 这就是卷积。
  • 深度学习做的事，说到底也是学这些核，只是层数更多、核更大、非线性更多。
python
import numpy as np
kernel = np.array([[-1, -1, -1],
                   [-1,  8, -1],
                   [-1, -1, -1]])            # 拉普拉斯：边缘增强
sharp = cv2.filter2D(gray, -1, kernel)

理解了卷积，你就理解了 90% 的经典图像处理和一半的深度学习。

Q3. 人脸识别到底分几步

四步，一步都不能跳

步骤输入输出出错会怎样
检测整张图人脸框漏检 / 误检，后面全白搭
对齐人脸框摆正的脸侧脸和正脸距离被拉远
提特征摆正的脸128/512 维向量同类距离不稳定
比对两个向量相似度阈值定不下

检测：三代方法

方法原理速度准确现状
Haar 级联手工特征 + 级联分类器很快一般，侧脸差老代码里还在用
HOG + SVM梯度方向直方图快中dlib 的经典实现
CNN（DNN 模块）学出来的特征中（可 GPU）好现在的默认选择
python
# OpenCV 自带的 Haar 分类器，一行就能跑（虽然老，但零依赖）
cascade = cv2.CascadeClassifier(
    cv2.data.haarcascades + 'haarcascade_frontalface_default.xml')
faces = cascade.detectMultiScale(gray, scaleFactor=1.1,
                                 minNeighbors=5, minSize=(48, 48))
for (x, y, w, h) in faces:
    cv2.rectangle(img, (x, y), (x + w, y + h), (0, 255, 0), 2)

scaleFactor 决定金字塔多密，minNeighbors 决定多严格。 这两个参数要按场景调，没有通用值。

对齐：最容易被跳过、也最影响结果的一步

  • 做法：找 5 个关键点（两眼、鼻尖、两嘴角）， 算一个仿射变换，把它们摆到标准位置上。
  • 为什么必须做：同一个人的侧脸和正脸，在特征空间里的距离可能比两个不同的人还远。
python
# 思路（具体实现用 dlib / mediapipe 拿关键点）
M = cv2.estimateAffinePartial2D(src_points, dst_points)[0]
aligned = cv2.warpAffine(face, M, (112, 112))

提特征与比对

  • 现代做法是把对齐后的脸丢进一个网络，得到一个向量（embedding）。
  • 关键性质：同一个人的向量距离近，不同人的远 —— 距离本身有了语义。
python
# 伪代码：emb 是 512 维单位向量
sim = float(np.dot(emb_a, emb_b))       # 余弦相似度，-1 ~ 1
if sim > 0.55:                          # 阈值必须用你自己的数据标定
    print('同一个人')

阈值不能抄别人的。它取决于模型、对齐质量、你的误拒/误识代价。 拿你自己的数据跑一遍 ROC，再选点。

工程上的坑

现场最常见的四件事

  1. 光照：侧光会让脸半边过曝、半边死黑。 → 直方图均衡（cv2.equalizeHist）或 CLAHE，先试。
  2. 分辨率不够：人脸框小于 64×64 时，特征基本不可用。 → 要么换镜头，要么限定距离。算法救不回来。
  3. 侧脸与遮挡：戴口罩时的识别率会掉得很明显。 → 工程上要给出「置信度低就要求重试」的降级路径。
  4. 活体：拿张照片就能骗过的系统不能算识别系统。 → 需要额外的活体检测（眨眼、深度、红外）。

一条务实的验收清单

  • 采集你自己的数据：同一人不同光照/角度，不同人相似长相。
  • 报告三个数，不要只报准确率：
    • 误识率 FAR：把别人认成你
    • 误拒率 FRR：把你认成别人
    • 通过时间：现场能不能接受
  • 定一个降级策略：置信度低时要求再试一次，而不是硬判。

能说清楚「什么情况下它会失败」的系统，才是能交付的系统。

小结

  1. 图像就是三维数组；记住 BGR、img[y, x]、(宽, 高) 这三个坑。
  2. OpenCV 是 C++ 库的 Python 绑定，imread 失败返回 None 而不报错。
  3. 卷积是图像处理里唯一的动作，换核就是换效果。
  4. 识别分检测 → 对齐 → 提特征 → 比对四步，对齐最容易被跳过也最影响结果。
  5. 阈值要用自己的数据标定，并且必须准备降级策略。
